House SDLC skills

The house SDLC: a records-first software-development process, run by three cooperating Claude Code skills over a small CLI kernel. The records on disk are the process — so a session that dies loses nothing, and every gate between stages fails closed.

The three skills

shape

house-shaper

Turns something fuzzy — an idea, a backlog line, an audible mid-build — into work that can be built: a spec you approved, a plan, an independent plan-check verdict, and a versioned kickoff brief.

conduct

house-orchestrator

Drives one slice from ready to merged — dispatching a build session per plan unit, holding every gate, running the merge review, reconciling the docs — and never edits product code itself, so the review it holds stays independent.

build

house-builder

Implements exactly one unit from exactly one kickoff brief, self-reviews it against the plan, reports back through the records, and is then torn down.

The kernel underneath

The house CLI keeps three layers of records with exactly one writer each: the slice directory (docs/slices/<id>/ — spec, plan, task list, gate records, unit reports), the append-only event log at .house/events.jsonl that only the CLI and its hooks ever write, and a derived cache you can delete and rebuild byte-for-byte. Gates are enforced there rather than remembered: house state refuses to advance a slice when the record saying a gate passed is absent, and refuses again when the record exists but its verdict is not a passing one. A false stop is cheap; a false pass is not.
